# src 리뷰 후속 수정 보고서

작성일: 2026-09-27. 기존 [PR #1](https://github.com/AlphaBs/FishSyncClient/pull/1)은 `6e91fd3`으로 main에 머지했다. 이 후속 작업은 해당 main에서 분기한 `codex/sync-safety-fixes`에 작성했다.

사용자가 지정한 1·2·3·5·8·11·12번을 수정했다. 4·6·7·9·10번은 보류한다. 번호는 원래 전체 src 리뷰의 번호를 유지한다.

## 해결한 항목

| 번호 | 원래 문제 | 수정 결과와 검증 |
| --- | --- | --- |
| 1 | 원본 읽기/전송 실패로 기존 파일이 비워짐 | 로컬 대상은 같은 디렉터리의 임시 파일에 복사한 후, 비교기가 있는 API에서는 검증까지 통과해야 교체한다. HTTP 404, 부분 전송 실패, 취소, 검증 실패 시 기존 파일 보존/새 파일 미설치/임시 파일 정리를 검증했다. 자기 자신으로의 복사도 내용이 보존된다. |
| 2 | 링크를 따라 루트 밖의 파일에 접근·삭제 | 루트 및 상위 경로, 열거 항목, 읽기·쓰기·삭제·교체 경로에서 링크/reparse point를 거부한다. 디렉터리 링크를 재귀 탐색하지 않는다. 외부 파일 불변, 열거 후 경로가 링크로 바뀐 상황, dangling 링크를 검증했다. Windows에서는 권한 없이 만들 수 있는 정션으로 같은 테스트를 실행한다. |
| 3 | 호출 실패를 반환한 뒤에도 복사가 계속됨 | 입력 열거, Queue 진행률 콜백, 취소로 enqueue가 실패하면 블록을 fault 처리하고 Completion을 기다린 뒤 원래 예외를 반환한다. SendAsync가 false를 반환하면 enqueue를 중단한다. 취소를 무시하는 사용자 정의 복사도 종료를 기다리는지 검증했다. 로컬 진행률 콜백 실패 때도 내부 복사 Task를 끝까지 관찰한다. |
| 5 | 정상 대문자 hex 체크섬을 오류 처리 | 로컬 및 메타데이터 비교기의 hex 비교를 OrdinalIgnoreCase로 통일했다. 대문자 MD5/SHA1의 실제 파일 교체·검증 성공과 메타데이터 비교를 검증했다. 알고리즘 이름 계약은 변경하지 않았다. |
| 8 | 체크섬 계산 중 취소 무시 | ComputeHashAsync에서 토큰을 읽기와 각 해시 처리 구간에 전달/검사한다. 로컬 비교기도 동일 토큰을 스트림에 전달한다. 사전 취소 시 미오픈, 읽기 중 취소 시 종료·스트림 해제, 여러 버퍼에 걸친 해시 결과를 검증했다. |
| 11 | 진행률 Position 이중 읽기로 바이트 누락 | 한 번 읽은 Position으로 delta와 이전 위치를 함께 계산한다. 콜백 도중 Position이 증가하는 제어된 실행에서 20바이트가 모두 보고되는지 검증했다. |
| 12 | 저장한 긴 버전 문자열을 128바이트로 잘라 읽음 | 기존 128바이트 한도를 저장 전 UTF-8 바이트 수로 검사한다. 제한 초과 입력은 기존 파일을 변경하기 전에 거부한다. 읽기는 경계까지 반복해 읽고, 이미 저장된 초과 파일은 잘린 버전 대신 null을 반환한다. ASCII/한글/이모지 경계와 비교·저장 시 공백 정규화를 검증했다. |

관련 구현: `LocalFileTransfer`, `LocalPathGuard`, `SyncFilePair`, `ParallelSyncFilePairSyncer`, 체크섬 비교기 및 `ChecksumAlgorithms`, `StreamProgressHelper`, `VersionManager`.

## 남은 작업과 적용 범위

- 선택한 7개 항목의 구현과 로컬 회귀 검증은 완료했다. 새 PR 검토·머지는 별도 단계다.
- 원래 리뷰의 구조 개선 의견인 경로 동일성/중복 정책 통일, 기대 메타데이터와 전송 상태 분리, 대상 생성 책임 명시, namespace·명명 정리는 별도 작업으로 남는다. private RuleFileComparer의 위치는 유지했다.
- 로컬 파일 교체는 파일 하나의 내용 단위다. 동기화 전체를 롤백하지 않으며, 다른 파일이 먼저 성공한 후 하나가 실패할 수 있다. 파일 권한·타임스탬프 등 메타데이터 동기화는 별도 계약을 추가하지 않았다.
- 사용자 정의 비교기는 검증 시 임시 파일을 가리키는 pair.Target에서 데이터를 읽어야 한다. pair.Source, 반환 결과의 대상, 무결성 오류의 대상 경로는 원래 파일 기준이다. 일반적인 비로컬 SyncFile 대상은 기존 스트림 쓰기 계약을 유지한다.
- 링크 검사는 정적인 링크와 열거 후 경로 변경을 차단하지만, 다른 프로세스가 검사와 I/O 사이에 디렉터리를 교체하는 경쟁 조건을 완전히 막는 OS 핸들 기반 보장은 아니다. 동기화 중 외부에서 디렉터리 구조를 바꾸지 않아야 한다. 그런 변경으로 임시 경로가 위험해지면 외부 삭제를 피하기 위해 임시 파일 정리가 실패할 수 있다.
- 12번 해결 방식은 버전 길이 제한을 없애는 방식이 아니다. UTF-8 128바이트까지 저장하며, 초과 입력은 ArgumentException으로 명시적으로 거부한다.
